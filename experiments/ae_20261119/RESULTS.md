# 정상만 학습하는 오토인코더 — 구간별 고장 탐지 (2026-11-19)

## 지침 변경
- 사용자 지시로 CLAUDE.md 3번("정상만 학습하는 오토인코더로 임의 변경 금지")과 다르게 정상만 학습하는 AE를 추가 실험함. 기존 코드·결과는 수정하지 않음.
- ID(무슨 고장인지 분류)는 이 실험에서 제외함. 사용자 판단: 모든 구간에서 소리가 나므로 정상/고장만 구분.

## 설정
- 코드: `experiments/ae_20261119/train_ae.py`. 구조도: `figures/ae_architecture.png` (`figures/make_ae_architecture.py`)
- 입력: `runs/baseline/cache`의 `id_views`(64 mel × 100 frame, dB). 앞 135–225°, 오른쪽 225–315°, 뒤 315–360° + 0–45°(2개 view로 따로 인코딩하고 이어 붙이지 않음). 45–135°는 사용하지 않음.
- 분할: 기존 `runs/baseline/splits/seed{42,43,44}.json`(녹음 단위 8:1:1, 고장 수 × RPM 층화, closed-source)
- 학습: 학습 분할의 정상 구간만 사용(1,440개). 정규화는 학습 정상 구간의 mel별 평균/표준편차.
- 모델: ConvAE(Conv2d s2 ×3 → latent 64 → ConvT ×3), masked MSE, AdamW 1e-3, batch 64, 최대 100 epoch. 조기 종료는 검증 정상 구간의 복원 오차(patience 15). GPU 약 50% 사용.
- 판정: 구간 점수 = view별 masked MSE를 길이 비율로 평균. 임계값은 검증 구간(정상 + 고장)에서 balanced accuracy가 최대가 되는 값으로 정하고, 시험에는 한 번만 적용.
- 출력: `runs/ae_normal_20261119/seed*/metrics.json`, `test_predictions.csv`, `history.json`, `summary.json`. 로그는 `runs/ae_normal_20261119.log`.

## 시험 결과 (구간 360개 = 정상 180 + 고장 180, 3 seed 평균 ± 표준편차)
| 지표 | 값 |
|---|---|
| ROC-AUC | 0.797 ± 0.005 |
| 정확도 (= balanced) | 0.750 ± 0.002 |
| 고장 재현율 | 0.880 ± 0.039 |
| 정상 특이도 | 0.620 ± 0.043 |
| 정밀도 | 0.699 ± 0.014 |
| F1 | 0.778 ± 0.006 |

- 구간별 AUC: 앞 0.79–0.80, 오른쪽 0.79–0.83, 뒤 0.82–0.86
- 고장으로 판정된 비율(종류별): Whine 0.87–1.0, Wind 0.94–0.95, Imbalance 0.76–0.95, PWM 0.76–0.95, Modulation 0.74–0.95. 정상을 고장으로 잘못 본 비율은 0.34–0.44.
- 참고: 같은 분할에서 고장 라벨로 학습한 기존 지도학습 ID baseline의 고장 AUC는 0.88 / 0.886 / 0.952, 정확도는 0.80–0.89. 이 실험은 고장 라벨 없이 학습했으므로 같은 조건의 비교는 아님.

## 한계
- closed-source holdout: 같은 원본 재생 음원이 학습과 시험에 모두 나옴. 처음 듣는 음원이나 실제 차량 부품 고장에 대한 성능을 입증한 것이 아님.
- 임계값은 검증 세트의 고장 라벨로 정함(학습에는 고장 라벨을 쓰지 않음).
- 정상 구간의 오탐이 많음(특이도 0.62). 오탐률은 같은 녹음의 고장 수에 따라 크게 달라짐(seed 42/43/44):
  - 고장 0곳 녹음의 정상 구간: 0.14 / 0.16 / 0.10
  - 고장 1곳: 0.63 / 0.38 / 0.45
  - 고장 2곳: 0.93 / 0.93 / 0.83
  → 다른 구간의 고장음이 정상 구간에도 들려서 복원 오차가 커지는 것으로 보임. 구간을 나눠도 소리가 완전히 분리되지 않음.
- 하이퍼파라미터(latent 64, 층 수, lr)는 탐색하지 않은 단일 설정.

## 추가: 구간 폭 90° / 60° / 30° 비교 (2026-11-19)
- 중심은 그대로(앞 180°, 오른쪽 270°, 뒤 0°), 폭만 변경. 60°·30°는 `build_cache_roi.py`로 WAV에서 새 캐시를 만듦(`runs/ae_roi60_20261119`, `runs/ae_roi30_20261119`). 새 캐시 코드로 90°를 만들면 기존 캐시와 값이 같음(최대 차이 0)을 2개 녹음으로 확인함.
- 실행: `train_ae.py --roi-width 60|30 --cache runs/ae_roi{60,30}_20261119`. 나머지 설정은 동일.

| 폭 | AUC | 정확도 | 재현율 | 특이도 | 정상 오탐: 고장 0곳 / 1곳 / 2곳 녹음 |
|---|---|---|---|---|---|
| 90° | 0.797 ± 0.005 | 0.750 | 0.880 | 0.620 | 0.13 / 0.49 / 0.90 |
| 60° | 0.800 ± 0.008 | 0.738 | 0.811 | 0.665 | 0.13 / 0.42 / 0.78 |
| 30° | 0.788 ± 0.018 | 0.731 | 0.881 | 0.581 | 0.21 / 0.49 / 0.89 |

- 결론: 구간을 좁혀도 AUC가 0.79–0.80으로 같음. 60°에서 정상 오탐이 조금 줄었지만, 그만큼 재현율도 떨어져서(임계값 위치 차이) 실질적인 개선은 없음. 30°는 오히려 약간 나빠짐(입력이 짧고 seed 편차가 큼).
- 해석: 정면 ±15°만 봐도 옆 구간 고장음이 비슷하게 섞임. 회전 마이크의 방향 구분이 이 섞임을 막을 만큼 날카롭지 않은 것으로 보임(가설, 마이크 지향성은 직접 측정하지 않음).
